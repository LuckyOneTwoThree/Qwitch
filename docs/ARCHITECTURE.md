# Qwitch 项目基线与架构设计文档

> 本文档为 **Qwitch** 项目的顶层技术与产品基线，用于对齐项目定位、核心边界、系统架构、安全规范、扩展协议及分期路线图。

---

## 1. 项目定义与核心边界

### 1.1 项目定位
**Qwitch** 是一款基于 [Tauri v2](https://v2.tauri.app/)（Rust + TypeScript）构建的**开源、本地优先（Local-First）桌面端 AI 工具多账号会话与额度管理应用**。

### 1.2 解决的核心问题
1. **状态切换成本高**：主流 AI 桌面客户端（Trae、WorkBuddy、Qoder 等）同一时刻通常仅维护单账号本地会话，多账号切换需频繁登出重登或手动备份目录。
2. **额度分散与黑盒化**：各平台免费额度、每日签到积分与重置周期割裂，缺乏统一的水位监控与手动领取入口。
3. **脚本工具门槛高且不安全**：命令行脚本缺乏直观 UI、往往明文保存凭据，且容易因高频轮询触发平台风控。

### 1.3 明确的非目标（Non-Goals）
* **不做云端同步服务**：不架设任何中心化后端，不上传任何用户凭据或使用记录。
* **不做无人值守高频挂机**：不提供激进的后台自动抢跑或高并发刷接口能力，所有敏感动作均由用户手动触发（Human-in-the-Loop）。后台自动刷新与自动签到**默认关闭**，需用户显式开启（自动签到开启需二次确认）；定时刷新仅在主窗口可见时执行。
* **不默认篡改设备指纹**：常规切号与领取严禁修改系统机器码或硬件指纹，避免触发平台反欺诈封号机制。
* **不内置闭源第三方依赖**：所有核心逻辑可编译、可审计。

## 2. 首发平台与系统约束（macOS + Windows）

### 2.1 存储路径规范
为避开 macOS TCC（Transparency, Consent, and Control）对后台/托盘进程访问 `~/Documents`、`~/Desktop`、`~/Downloads` 的权限拦截，应用的本地数据必须存入系统标准应用数据目录。应用使用 `qwitch` 作为内部目录名（并自动兼容迁移旧版 `quiver` 目录）：

* **macOS**：`~/Library/Application Support/qwitch/`
* **Windows**：`%APPDATA%\qwitch\`

### 2.2 跨平台抽象层（`PlatformHost`）
Rust 后端通过统一的平台宿主接口屏蔽操作系统差异：
* **应用探测**：自动扫描默认安装路径（macOS `.app` Bundle / Windows 注册表与常见安装目录），并允许用户在设置中手动覆盖路径。
* **进程生命周期管理**：支持检测目标客户端是否运行、发送优雅退出信号（macOS `SIGTERM` / AppleEvents，Windows 进程关闭与超时兜底）、等待文件锁释放后再写入会话并重新拉起客户端。
* **编码与路径安全**：统一处理 Windows Unicode 用户名路径与长路径问题。

## 3. 总体四层架构

```text
+-------------------------------------------------------------------+
| 1. UI 交互层 (TypeScript + React + Tailwind CSS)                  |
|    - 主窗口 Dashboard (账号池管理 / 额度水位 / 日志 / 设置)       |
|    - 系统托盘 Popover / 菜单 (高频快捷切号 / 一键查额与领取)      |
+-------------------------------------------------------------------+
                                  | Tauri IPC (Typed Commands / Events)
+-------------------------------------------------------------------+
| 2. 核心调度与防风控层 (Rust Core Engine)                          |
|    - 账号状态机 (Active / Expired / RateLimited / RiskPaused)     |
|    - 防风控调度器 (单队列串行 + 随机抖动延迟 + 幂等前置校验)      |
|    - 客户端冷切换协调器 (运行检测 -> 确认 -> 停进程 -> 写态 -> 重启)|
+-------------------------------------------------------------------+
                                  | Unified Adapter Contract (JSON Schema)
+---------------------------------+---------------------------------+
| 3a. 内置适配器 (Rust Native)    | 3b. 外部扩展适配器 (预留接口)   |
|     - Trae / Trae CN            |     - manifest.json 注册发现    |
|     - WorkBuddy                 |     - stdin/stdout JSON-RPC     |
|     - Qoder / Qoder CN          |       (支持 Python/Node/Sidecar)|
+---------------------------------+---------------------------------+
                                  |
+-------------------------------------------------------------------+
| 4. 存储与平台基础设施层 (Storage & Platform Host)                 |
|    - OS Keychain (macOS Keychain / Windows Credential Manager)    |
|    - 本地加密 SQLite (账号元数据 / 额度快照 / 脱敏操作日志)       |
|    - PlatformHost (macOS / Windows 文件、进程与钥匙串原语)        |
+-------------------------------------------------------------------+
```

## 4. 适配器能力模型与外部扩展预留

### 4.1 统一适配器能力（`ToolAdapter`）
每个工具适配器不必强行实现所有功能，而是通过**能力声明（Capabilities）**向核心层注册自己支持的操作：

* `auth_methods`：支持的登录态导入方式（`webview_oauth` / `local_import` / `token_paste`）。
* `supports_quota_query`：是否支持查询剩余额度、套餐等级与重置时间。
* `supports_daily_claim`：是否支持每日签到/积分领取（如 WorkBuddy 成长中心、Qoder CN 每日 Credits）。
* `supports_client_switch`：是否支持本地桌面端一键冷切换（以及后续是否支持 `--user-data-dir` 多开隔离）。

### 4.2 外部适配器协议预留（Extensible Plugin Bridge）
第一期内置 **Trae**、**WorkBuddy**、**Qoder** 三个 Rust 原生适配器以保证稳定性；同时从 v0.1 起，所有 Adapter 的输入输出结构体均采用**纯 JSON 可序列化 Schema**。

后续外部扩展目录约定为 `<app_data>/adapters/<adapter_id>/`：
* `manifest.json`：声明适配器 ID、名称、支持平台、能力清单、可执行入口命令及超时策略。
* **通信协议**：核心引擎通过子进程 `stdin/stdout` 发送单行 JSON-RPC 请求（`inspect_quota`、`claim_daily`、`apply_session`），外部脚本（Python / Node / 二进制 Sidecar）返回标准化 JSON 响应与统一错误码。

## 5. 防风控与安全基线

### 5.1 每日领取防风控四原则
1. **幂等先查后领**：执行领取前必须先调用状态查询接口，确认处于“未领取”状态才发出领取请求，避免重复发包。
2. **串行错峰执行**：一键触发“全部领取”时，按工具/账号队列**严格串行**，相邻请求之间注入随机抖动延迟（默认 `1500ms - 3500ms`，后端强制下限 500ms）。同一工具出现风控/限流错误即熔断该工具剩余账号；批量任务重入直接拒绝。
3. **错误即刻熔断**：遇到 `401`（凭据失效）、`403`（权限/风控拒绝）或验证码挑战时，立即将对应账号置为 `Expired` 或 `RiskPaused`，中止后续动作并提示人工处理，绝不循环重试。
4. **会话特征保真**：请求头与凭据格式尽量贴合本机官方客户端原生特征，不伪造异常并发或批量探测接口。

### 5.2 本地数据安全规范
* **主密钥托管**：应用首次初始化时生成随机加密主密钥，存入系统原生钥匙串（macOS Keychain / Windows Credential Manager）。
* **凭据加密存储**：所有 Token、Cookie、加密信封快照均加密后存入本地 SQLite；内存中使用完毕后及时清理，日志输出强制脱敏（UID 仅保留前后缀，严禁打印完整 Token）。
* **加密导出备份**：后续提供备份导出功能时，强制使用用户口令派生的对称加密（如 AES-256-GCM），不默认导出明文凭据。

## 6. UI/UX 与交互基线

### 6.1 视觉与体验原则
* **极简克制**：采用现代桌面端卡片式布局，自适应系统浅色/深色模式，信息层级清晰（工具 -> 账号 -> 额度水位 -> 状态胶囊）。
* **状态明确**：所有账号状态通过语义化标签区分：`正常`、`待领取`、`已领取`、`凭据过期`、`风控暂停`。

### 6.2 双端协同交互
* **系统托盘（高频场景）**：
  * 左键点击呼出轻量 Popover 面板，按工具展示当前本机活跃账号与剩余额度进度条。
  * 支持直接点击目标账号触发**一键切号**，或点击**一键领取**，操作结果通过应用内分级 Toast 轻提示反馈（主窗口与托盘均挂载）。
* **主窗口 Dashboard（管理场景）**：
  * 账号增删改、分组备注、三轨导入引导（本机导入 / WebView 登录 / Token 粘贴）。
  * 切换桌面端前的**安全确认弹窗**（提醒用户保存 IDE 中未保存的工作内容）。
  * 本地操作记录与诊断视图（查看失败原因、客户端路径检测状态）。

## 7. 分期迭代路线图

### Phase 1 — v0.1 MVP（核心闭环）
* 完成 Tauri v2 + React + TypeScript + Rust 双平台（macOS / Windows）基础工程骨架。
* 落地 OS Keychain + 本地加密 SQLite 存储层与 `PlatformHost` 抽象。
* 实现 **Trae**、**WorkBuddy**、**Qoder** 三个内置适配器（支持本机导入/Token 导入、查额、手动防风控串行领取）。
* 实现目标桌面客户端的**一键冷切换**（安全确认 -> 关进程 -> 写会话 -> 重启）。
* 完成主窗口 Dashboard 与系统托盘 Popover 的高颜值基础交互。

### Phase 2 — v0.2 体验深化与生态预留
* 为 Trae 等支持内置 WebView 登录的适配器补全 OAuth / 2FA 登录流。
* 上线外部适配器加载器（`manifest.json` + JSON-RPC），支持社区热插拔新工具。
* 针对 VS Code 内核工具（Trae / Qoder）增加**多开实例管理**（基于 `--user-data-dir` 隔离）。
* 支持加密 JSON 导入导出备份与多语言（中 / 英）。

### Phase 3 — v0.3 进阶调度（远期延展）
* 探索本地统一 API 网关 / 代理模式（针对支持标准协议的工具/账号池，提供本地端口自动故障转移与额度路由）。
