# Qwitch 号池编排与 Agent 指向产品形态及 UI/UX 交互规范（v2）

> **定位视角**：资深产品经理 · UI 设计师 · 交互体验设计师（UX）  
> **设计基线**：对齐 [品牌定位与命名规范](BRAND_IDENTITY.md) 与 [UI 视觉质感基线](UI_VISUAL_REFINEMENT.md)——延续「克制、精准、Local-First 精密仪表盘」风格，拒绝后台模板感与信息过载。

## 1. 产品心智模型与核心差异化

### 1.1 「号池管账号底座 · 模型是一等选择项」

```text
  ① 账号资产层（已有）          ② 分层号池与模型（第一舞台）     ③ 多池挂载（M:N Agent）      ④ 路由观测（建立信任）
  ┌──────────────────┐        ┌──────────────────────┐       ┌──────────────────────┐       ┌──────────────────────┐
  │ 7 大 AI 工具养号  │  ───►  │ T1/T2/T3 账号底座     │ ───►  │ 单 Agent 挂载多号池   │ ───►  │ 锁定模型 · 同模切号   │
  │ 查额 · 签到 · 切号│        │ 显式勾选对外模型      │       │ 下拉列表实时预览 + ★ │       │ Prompt Cache · TTFT  │
  └──────────────────┘        └──────────────────────┘       └──────────────────────┘       └──────────────────────┘
```

### 1.2 v2 解决的五个关键产品与 UX 问题

1. **为什么模型必须显式直出，而不是黑盒隐藏？**
   客户端在真正干活时**模型永远是首要选择项**，网关绝不应该私自把用户选的模型偷换成别的模型。在 Qwitch v2 中，号池管理账号底座与 `T1 主力 / T2 备选 / T3 付费兜底`，同时由用户显式勾选对外开放的模型清单；消费端在下拉菜单里**直接选具体模型**，后台自动在所有具备该模型的账号间按梯队与同工具水位切号。
2. **为什么不能跨不同工具比对「剩余百分比」？**
   `Trae CN` 按次数、`WorkBuddy` 按可攒积分、`Qoder CN` 按每日刷新额度、`API Key` 按余额，量纲完全不同。Qwitch v2 采用**两层调度**：跨工具严守 `T1 → T2 → T3` 与编排顺位（API Key 强锁 T3 兜底），仅在**同工具多个账号间**按 `quota_snapshots` 水位降序竞争。
3. **1 个 Agent 可以挂载多个号池吗？**
   **完全支持（M:N）**。用户可以把「主力全栈 Coding 池」和「深度推理长文池」同时挂到 Claude 桌面版、OpenCode 或 Codex，并在 Qwitch 卡片内的**客户端模型下拉菜单实时预览**中指定其中一个模型为 `★ 默认模型`。
4. **如何解决左侧导航与双栏布局拥挤？**
   - 主侧栏采用 **方案 A**：一级侧栏收拢为 6 个纯粹功能域（`账号资产`、`号池编排`、`Agent 指向`、`路由观测`、`操作日志`、`设置与环境`），7 大工具筛选下沉到账号工作区顶部的横向滚动胶囊条；
   - `号池编排` 采用 **宽屏双栏独立滚动 + 右侧 3 分页**：左栏号池列表始终可见不滚丢，右栏固定头部 + `模型与账号轨道`（首屏直达）/ `调度策略与护栏` / `已挂载 Agent`。
5. **如何不装后端就能连续体验完整的 Failover 与亲和缓存？**
   在 `PoolSimulationModal` 中可选定具体 `Agent + 号池 + 模型` 发起演练，注入 `429` 冷却后点击 **「继续发下一条（验证冷却跳过与亲和）」**，同会话直接验证 1 号处于冷却被跳过、2 号通过 Prompt Cache 亲和直接接管。

## 2. 信息架构（IA）与导航设计

### 2.1 主窗口侧栏分级（方案 A · 收拢为 6 个一级功能域）

```text
Qwitch 侧栏 (w-52)
├─ 品牌头部：Qwitch Logo + 号池与多模型网关
├─ 【工作台与路由】
│    ├─ 账号资产  [总账号数]     ← 顶部内置 7 家工具横向胶囊条（全部 / 7 工具 + 运行绿点）
│    ├─ 号池编排  [号池数]       ← 双栏独立滚动 + 右侧 3 分页编排工作台
│    ├─ Agent 指向 [已挂/总数]   ← 多号池挂载 + 客户端模型菜单实时预览 + ★ 默认模型
│    └─ 路由观测  [采样数]       ← 同模型调度决策流水与 Attempt Timeline
├─ 【系统与审计】
│    ├─ 操作日志  [活跃数]
│    └─ 设置与环境 [更新红点]
└─ 底部锚点区
     ├─ 本地网关紧凑控制卡（状态灯 + :18425 + 启停开关）
     └─ 版本 / Local-First 加密库锁标 / 退出 Qwitch（新版时显示升级胶囊）
```

### 2.2 系统托盘 Popover（384×500px 轻量高频入口）

保持默认「账号与签到」零变化，切到 **`号池与指向`** 页签时：
- 顶部一行网关总开关（绿灯运行中 / 灰灯已停止 + 端口）；
- 4 个目标 Agent 紧凑卡：展示已挂号池数 / 模型数与漂移重启状态，支持直接在下拉框中热切换 `★ 默认模型`（甚至一键追加挂载新号池并设为默认）；
- 活跃号池聚合水位速览 + 底部快捷入口「打开主面板编排号池」。

## 3. 核心视图与交互细节规范

### 3.1 视图一：号池编排（`PoolsView`）

1. **顶部流向摘要带**：`可用账号源 ──► 活跃号池 ──► 已挂载 Agent（支持多池）` + `模拟打流 / Failover` + `新建号池`。
2. **左侧号池清单（`@3xl` 下独立滚动）**：展示场景徽标、策略短标（如 `同工具水位`）、启停开关、对外模型摘要标签、堆叠工具图标 + 水位条、已挂载 Agent 标签。
3. **右侧精密编排面板（固定头 + 3 分页独立滚动）**：
   - **分页 1 · `模型与账号轨道`（默认首屏）**：
     - **对外开放的模型列表**：逐个控制是否对外暴露、查看就绪账号数与梯队分布（如 `4/5 账号就绪 (T1×2 · T2×2 · T3×1)`）、复制 Claude 底层伪装 ID（非 Anthropic 模型自动伪装为 `mythos-qwitch-*`；`claude-*` 直过白名单）、配置「严格锁模（全灭报错，默认）」vs「全灭后显式降级模型」，以及一键 `测此模型`；
     - **池内账号底座（按 `T1 主力` / `T2 备选` / `T3 付费兜底` 分组）**：支持上下调整顺位、调整梯队（API Key 锁定 `T3`）、**行内直接点击模型标签多选/取消该账号开放的模型**、注入模拟 `429` 与倒计时解除冷却。
   - **分页 2 · `调度策略与护栏`**：异构/同构口径明确提示条 + 4 种梯队内策略选择卡 + 会话亲和模式 + 防桌面活跃号互踢 / 401 单飞刷新 / T3 API Key 兜底 / 429 冷却秒数。
   - **分页 3 · `已挂载 Agent`**：展示挂载了此号池的所有 Agent、从本池获得的模型列表与 `★ 默认` 标识、以及通过 Diff 确认的卸载操作。

### 3.2 视图二：Agent 指向与挂载台（`AgentBindingsView`）

1. **顶部环境自检条**：本地网关 + 插件桥宿主模拟切换 + 全局代理模拟切换 + 重新探测 + 网关启停。
2. **4 张目标 Agent 挂载卡（`@3xl:grid-cols-2`）**：
   - **多号池勾选区**：可同时勾选多个号池挂载到同一个 Agent，显示每个号池开启的模型数；
   - **客户端模型下拉菜单实时预览**：实时渲染客户端内会列出的模型（重名时自动带号池后缀区分），点击 **`设为默认`** 即设为该 Agent 的 `★ 默认模型`，Claude 卡片附带伪装 ID 对照标注；
   - **4 端专属能力与告警**：Codex `app-server` 精准重启与代理 502 预警、Claude macOS 独立双开与白名单说明、DSH `.credentials.yaml` 漂移修复、OpenCode `v2`/`v1` Schema 切换。
3. **底部通用标准端点卡**：支持选池 + 选具体模型生成 `OPENAI_BASE_URL` / `ANTHROPIC_BASE_URL` 环境变量。

### 3.3 核心弹窗组（全部经 `ConfigDiffModal` 透明把关）

1. **`CreatePoolModal`**：4 场景模板 + `(账号 × 多模型 Pills + T1/T2/T3 梯队)` 矩阵选择 + 实时汇聚将暴露模型清单 + CodeArts `client_readonly` 拦截与独立 OAuth 解锁 + 若勾选直挂 Agent，创建后自动逐一弹出 **`ConfigDiffModal`** 预览 Diff 并确认挂载。
2. **`AddPoolMembersModal`**：支持新账号勾选与已有账号**继续追加多模型槽位**（已入池模型置绿不可重复选）。
3. **`BindAgentModal`**：以追加语义把本池加入多个 Agent 挂载列表（保留其已有号池），每行均支持直接预览 Diff。
4. **`PoolSimulationModal`**：按 `Agent → 号池 → 具体目标模型 → 故障模式` 发起模拟，支持**「继续发下一条（验证冷却跳过与亲和）」**连续演练。
5. **`ConfigDiffModal`**：展示将挂载号池列表、`★ 默认模型`、Stash 加密备份机制及完整 Before / After 配置对比。

## 4. 视觉令牌与无障碍约束

- **颜色与对比度**：主 CTA 严格使用 `.btn-primary`（浅色 `brand-700` 白字 ≥ 5.5:1，深色 `brand-400` 黑字 ≥ 10.4:1）；卡片内主操作使用 `.btn-brand-soft`；警告/冷却/漂移使用 `amber-500`，熔断/失效使用 `rose-500`。
- **数字排版**：所有额度百分比、剩余积分、TTFT 毫秒数、Token 数、端口与冷却倒计时均启用 `tabular-nums`（等宽数字不抖动）。
- **容器自适应**：严格遵循 `@container` 规则（`@sm` / `@3xl` / `@5xl`），`PoolsView` 在 `@3xl` 以上启用独立滚动分栏、窄屏自动流式降级为整页滚动，确保 `860×580` 最小窗口下无文字截断或横向破版。
- **键盘与无障碍**：所有弹窗支持 `Escape` 关闭与 `Tab` 焦点陷阱；导航项、开关、Tablist 完整标注 `aria-current`、`aria-selected`、`aria-pressed` 与 `aria-label`。
