# Qwitch 号池编排与 Agent 指向产品形态及 UI/UX 交互规范（v2）

> **定位视角**：资深产品经理 · UI 设计师 · 交互体验设计师（UX）  
> **设计基线**：对齐 [品牌定位与命名规范](BRAND_IDENTITY.md) 与 [UI 视觉质感基线](UI_VISUAL_REFINEMENT.md)——延续「克制、精准、Local-First 精密仪表盘」风格，拒绝后台模板感与信息过载。  
> **前端原型范围**：覆盖主窗口 Dashboard 3 个新增一级视图、交互弹窗、以及系统托盘 Popover 双态面板，可直接在 `npm run dev` 浏览器 Mock 模式下完整体验全部交互流。

## 1. 产品心智模型与核心差异化

### 1.1 「号池管账号底座 · 模型是一等选择项」

```text
  ① 账号资产层（已有）          ② 分层号池与模型（第一舞台）     ③ 多池挂载（M:N Agent）      ④ 路由观测（建立信任）
  ┌──────────────────┐        ┌──────────────────────┐       ┌──────────────────────┐       ┌──────────────────────┐
  │ 7 大 AI 工具养号  │  ───►  │ T1/T2/T3 账号底座     │ ───►  │ 单 Agent 挂载多号池   │ ───►  │ 锁定模型 · 同模切号   │
  │ 查额 · 签到 · 切号│        │ 显式勾选对外模型      │       │ 下拉列表实时预览 + ★ │       │ Prompt Cache · TTFT  │
  └──────────────────┘        └──────────────────────┘       └──────────────────────┘       └──────────────────────┘
```

### 1.2 v2 解决的五个关键产品与 UX 问题

1. **为什么模型必须显式直出，而不是黑盒隐藏？**
   客户端在真正干活时**模型永远是首要选择项**，网关绝不应该私自把用户选的模型偷换成别的模型。在 Qwitch v2 中，号池管理账号底座与 `T1 主力 / T2 备选 / T3 付费兜底`，同时由用户显式勾选对外开放的模型清单；消费端在下拉菜单里**直接选具体模型**，后台自动在所有具备该模型的账号间按梯队与同工具水位切号。
2. **为什么不能跨不同工具比对「剩余百分比」？**
   `Trae CN` 按次数、`WorkBuddy` 按可攒积分、`Qoder CN` 按每日刷新额度、`API Key` 按余额，量纲完全不同。Qwitch v2 采用**两层调度**：跨工具严守 `T1 → T2 → T3` 与编排顺位（API Key 强锁 T3 兜底），仅在**同工具多个账号间**按 `quota_snapshots` 水位降序竞争。
3. **1 个 Agent 可以挂载多个号池吗？**
   **完全支持（M:N）**。用户可以把「主力全栈 Coding 池」和「深度推理长文池」同时挂到 Claude 桌面版、OpenCode 或 Codex，并在 Qwitch 卡片内的**客户端模型下拉菜单实时预览**中指定其中一个模型为 `★ 默认模型`。
4. **如何解决左侧导航与工作台层级拥挤？**
   - 主侧栏收拢为 **5 个纯粹一级功能域**（`账号资产`、`Agent 接入与调度`、`路由观测`、`操作日志`、`设置与环境`），7 大工具筛选下沉到账号工作区顶部的横向滚动胶囊条；
   - 合并独立号池页，收敛为以 Agent 为中心的 **3 分区工作台**（`模型配置` / `账号调度` / `接入设置`）：选中目标 Agent 后直接按订阅工具勾选开放模型、设为 `★ 默认模型`、编排同工具主备顺位并一键同步至全部 Agent。
5. **如何便捷验证 Failover 与亲和缓存？**
   在 `PoolSimulationModal` 中可选定具体 `Agent + 号池 + 模型` 发起连通性测试，注入 `429` 冷却后点击 **「继续发下一条（验证冷却跳过与亲和）」**，同会话直接验证 1 号处于冷却被跳过、2 号通过 Prompt Cache 亲和直接接管。

## 2. 信息架构（IA）与导航设计

### 2.1 主窗口侧栏分级（5 个一级功能域）

```text
Qwitch 侧栏 (w-52)
├─ 品牌头部：Qwitch Logo + 号池与多模型网关
├─ 【工作台与路由】
│    ├─ 账号资产         [总账号数]     ← 顶部内置 7 家工具横向胶囊条（全部 / 7 工具 + 运行绿点）
│    ├─ Agent 接入与调度 [已挂/6]       ← 6 大 Agent 切换 + 3 分区工作台（模型配置 / 账号调度 / 接入设置）
│    └─ 路由观测         [采样数]       ← 同模型调度决策流水、失败/Failover 筛选与 Attempt Timeline
├─ 【系统与审计】
│    ├─ 操作日志         [活跃数]
│    └─ 设置与环境       [更新红点]     ← 含本地网关端口设置、占用检测与运行中桌面 Agent 批量重启
└─ 底部锚点区
     ├─ 本地网关快捷启停控制卡（状态灯 + 启停开关，支持处理中忙碌态）
     └─ 版本 / Local-First 加密库锁标 / 退出 Qwitch（新版时显示升级胶囊）
```

### 2.2 系统托盘 Popover（384×500px 轻量高频入口）

保持默认「账号与签到」零变化，切到 **`号池与指向`** 页签时：
- 顶部一行网关总开关（绿灯运行中 / 灰灯已停止 + 端口，带忙碌态防连点）；
- 6 个目标 Agent 紧凑卡：展示已挂号池数 / 模型数与漂移/待重启状态，支持直接在下拉框中热切换 `★ 默认模型`（或一键追加挂载并设为默认）；
- 活跃号池聚合水位速览 + 底部快捷入口「打开主面板编排号池」。

## 3. 核心视图与交互细节规范

### 3.1 视图一：Agent 接入与调度（`AgentBindingsView`）

1. **顶部环境自检条**：本地网关状态与端口快捷入口（点击地址打开 `GatewayPortModal` 端口/占用检测弹窗）+ 插件桥状态 + 本机回环/全局代理状态 + 全部清除。
2. **6 张目标 Agent 切换卡（响应容器宽度自适应多列）**：覆盖 **Codex 桌面版、Claude 桌面版、DeepSeek Harness (DSH)、OpenCode、MiMo Code、ZCode**，展示协议徽标、挂载状态、默认模型与开放模型计数；未安装客户端不显示无效重启按钮。
3. **当前 Agent 3 分区工作台**：
   - **分区 1 · `模型配置`**：按订阅工具横向切换（有账号的工具前置），支持「刷新真实模型」、搜索框与「全部 / 已勾选 / 免费低倍率 / 主力旗舰」快捷筛选、批量工具栏（全选当前 / 仅选免费低倍率 / 反选 / 清空本工具），勾选即实时写入配置，并支持行内 `设为默认`。
   - **分区 2 · `账号调度`**：同工具主备账号顺位编排（支持上移/下移/设为主号/按额度排顺位/临时冷却/参与调度开关）、策略选择（主号优先自动切备 / 剩余额度优先 / 锁定消耗当前主号）、跳过桌面端活跃账号（防互踢）、429 冷却时长与「同步到全部 Agent」。
   - **分区 3 · `接入设置`**：6 端专属兼容说明与选项（Claude macOS 独立双开与 `mythos-qwitch-*` 映射、Codex `qwitch_models.json` 与保旧线程说明、DSH 双凭据校验、OpenCode `v1`/`v2` Schema 切换、MiMo Code / ZCode 协议接入提示），以及底部通用标准端点环境变量生成与一键复制卡。

### 3.2 视图二：路由观测（`RoutingTraceView`）

- 4 张 KPI 指标卡：近期路由采样（成功率）、同模型 Failover、亲和缓存命中率、上游通道就绪度；
- 筛选栏：关键词搜索（带一键清空）、来源 Agent 筛选、「仅看失败（带计数）」、「仅看 Failover 切号」与「测试路由」入口；
- 可展开决策链路流水与空态引导（筛选无匹配时提供「清除筛选条件」，无记录时引导立即测试路由）。

### 3.3 核心弹窗组（全部经 `ConfigDiffModal` 透明把关）

1. **`GatewayPortModal`**：修改本地网关端口（1024–65535 严格整数校验）与实时端口占用检测，修改自动重启网关并同步已挂载 Agent。
2. **`PoolSimulationModal`**：按 `Agent → 号池 → 具体目标模型 → 故障模式` 发起连通性测试，支持**「继续发下一条（验证冷却跳过与亲和）」**连续演练。
3. **`ConfigDiffModal`**：展示将挂载号池列表、`★ 默认模型`、Stash 加密备份机制及完整 Before / After 配置对比。

## 4. 视觉令牌与无障碍约束

- **颜色与对比度**：主 CTA 严格使用 `.btn-primary`（浅色 `brand-700` 白字 ≥ 5.5:1，深色 `brand-400` 黑字 ≥ 10.4:1）；卡片内主操作使用 `.btn-brand-soft`；警告/冷却/漂移使用 `amber-500`，熔断/失效使用 `rose-500`。
- **数字排版**：所有额度百分比、剩余积分、TTFT 毫秒数、Token 数、端口与冷却倒计时均启用 `tabular-nums`（等宽数字不抖动）。
- **容器自适应**：严格遵循 `@container` 规则（`@sm` / `@lg` / `@2xl` / `@3xl` / `@6xl`），确保 `860×580` 最小窗口下无文字截断或横向破版。
- **键盘与无障碍**：所有弹窗支持 `Escape` 关闭与 `Tab` 焦点陷阱；导航项、开关、Tablist 与忙碌态完整标注 `aria-current`、`aria-selected`、`aria-pressed`、`aria-busy` 与 `aria-label`。
