Design Review · Deep Pass

Qwitch 已经有一套设计系统，
但它还没有真正被执行。

这一轮评审不做表层美化。我把界面跑起来、量了尺寸、读了源码，结论是：问题不在「好看不好看」，而在层级契约被稀释——每张卡片都在用同样的重量说话，于是用户的眼睛找不到入口。以下所有判断都附实测数字与可执行处方。

01

结论

一段话说完，然后给数字。

判断
令牌层（品牌色 / 圆角 / 阴影 / 动效）已经做得比多数商业产品扎实，但令牌只覆盖了「品牌色」这一个维度。 中性色仍是 1200 余处字面色阶 + 944 处 dark: 成对覆盖，字号与控件高度各有 7–8 档且不在 4px 网格上。 结果是：系统存在，但每个组件都在各自谈判，视觉一致性靠人工对齐维持，随版本必然漂移。
症状
单张账号卡上有 3 枚徽标（套餐=emerald 描边、状态=emerald 实底、签到=中性灰）再叠一枚品牌图标， 四个小色块里三个是绿，其中两个绿的语义还不同；「正常」这个对 90% 账号成立的徽标常驻； 能力清单 ✓ 切号·查额·签到就绪 用成功色表达「功能可用」，与真实故障争夺注意力。 颜色不再代表状态，只代表「这里有个东西」。
代价
首屏 900px 里有 308px（34%） 被标题、吸顶筛选、指标条、分组头吃掉，且副标题与指标条重复播报同样的三个数字； 卡片 203px 中有 23px 纯粹用于把套餐徽标单独放一行，12 张卡共浪费 276px——接近一整屏的 1/3。
方向
不加新东西，只做减法与收敛：一卡一重音（每张卡只允许一个「重」元素）、状态独占颜色、元数据一律中性、 去掉卡内第二层盒子、把 8 档字号收到 5 档、把 7 档控件高度收到 3 档。目标是在同屏多看到约 1.45 倍卡片的同时， 让每张卡的扫读时间从「找」变成「看」。

03

六个结构性问题

按「改完之后收益 / 改动成本」排序。前三个是 P0，因为它们每天都在消耗用户的注意力。

P0-1

套餐徽标独占一行，把「图标—名称」这对本应对齐的元素拆散了

层级
证据

实测卡片头部：套餐徽标占 y 15–36px，名称从 y 38px 才开始； 品牌图标 36px 起于 y 16，其视觉中心在 34px——正好落在徽标那一行，而不是名称上。

title.top = 38 · icon.center = 34
card.h = 203 → 164

套餐徽标内联到名称右侧，作为 18px 高的中性细边框 chip（不是彩色徽标）。 名称与图标共享同一行中心线，元信息统一缩进到图标右侧 39px 处形成一条垂直基线。

P0-2

三个徽标加一个品牌图标，其中两个绿得毫无区别 —— 颜色失去了信息量

语义
证据

Trae 账号卡上：套餐 Pro 用 emerald 描边（toolRegistry.badgeClass）， 状态 正常 用 emerald 实底（StatusBadge）， 签到 今日已领 用中性灰，品牌图标又是一枚 emerald 渐变块。

4 个承载信息的小色块、3 个是绿、其中 2 个绿的语义还不一样。 用户无法从颜色判断「哪个是说账号状态、哪个只是说套餐等级」。

更关键的是：正常 对绝大多数账号恒为真。当 90% 的卡都挂着一枚绿色徽标， 用户会对绿色脱敏——真正需要被看见的琥珀色「凭据过期」反而被稀释。

单卡徽标 3 枚 + 品牌图标 1 枚 = 4 个彩色块
正常态绿色信号 = 5 处（边框 / 外环 / 进度条 / 徽标 / 能力清单）
处方

立一条硬规则：颜色 = 状态，元数据 = 中性。套餐/别名/UID/设备 一律灰阶； 正常态不出现徽标，只保留名称右侧一枚 5px 的「在用」点；只有异常才升级为带文字的彩色徽标。

这样一张卡最多只允许一个彩色信号。扫视时「有颜色 = 有问题」，绿色回归「正在工作」这一个含义。

正常态：0 徽标 + 1 点 · 异常态：1 徽标
颜色预算：每卡 ≤ 1 处

P0-3

用「成功绿」表达「功能可用」，让每一张卡都在喊「我成功了」

语义
证据

✓ 切号 · 查额 · 签到就绪 这一行 12px emerald，位于额度条与按钮之间，是卡片视觉通路上最亮的一条水平带。 但它的含义只是「这个适配器声明了这三个能力」——是静态能力，不是运行结果。

代价有二：一是绿色对勾与真正的成功态（领取成功、同步成功）同形同色，语义冲突； 二是它占据了卡片里唯一的手风琴位置，把「最近同步时间」挤到了右侧角落。

该行高 22px / 卡 · 12 卡 = 264px
绿色对勾数 = 3 / 卡（与 12 张卡 = 36 个对勾）
处方

整行删除。能力不需要常驻显示——用户点按钮时若不可用，按钮自身禁用 + tooltip 已足够解释； 能力矩阵更适合放在设置页或卡片的溢出菜单里。

「最近同步时间」并入元信息行（u_8f3a****91c · 6 分钟前同步）， 过期时给琥珀色文字，正好利用右侧对齐形成稳定的时间列。

净省 22px/卡，且消除 36 个假成功信号
P1-4

一致性
证据

「领取」在主窗顶栏是 brand 实心，在账号卡是 sky-soft（btn-sky-soft），在托盘又是 brand 实心。

同一账号 TRAE 主力：主窗卡片把套餐徽标放在名称上方、状态徽标竖排两枚； 托盘则把套餐徽标内联在名称后、只留一枚状态徽标，额度文案也从 380 / 600 次 · 63% 变成 剩余 63% + 380 / 600 次 分列两端。 两个界面在教用户两套读法。

P1-6

令牌只覆盖了品牌色：语义层缺失，导致 944 处 dark: 手工配对

工程
证据

@theme 里定义了 --text-label-xs / --text-label-sm， 但全仓引用次数为 0；源码里写的是 149 处 text-[11px]。令牌定义了，但没人用。

中性色没有任何语义令牌：text-zinc-400 170 次、text-zinc-500 101 次、border-zinc-200 70 次…… 每一处都配一个 dark: 孪生类。改一次暗色背景，要动上百个文件。

dark: 变体 944 处 · tsx 共 18,439 行
text-[11px] 149 处 · text-label-* 引用 0 处
bg-white/[0.0x] 任意透明度 96 处
处方

补一层语义令牌：surface / surface-raised / border / border-strong / fg / fg-muted / fg-subtle， 在 :root 与 .dark 下各定义一次值。组件只写语义类， 删掉所有中性色的 dark: 孪生，预计减少 600+ 处条件类。

同时把 11px 收进 --text-label-xs，让「微标签」这个词在代码里有唯一出口。

04

目标形态：一张卡的收敛逻辑

把上面所有处方合成一个可评审的成品。下面的元素可悬停，尺寸与最终代码一致。

阅读顺序（眼动契约）

① 这是谁（名称 600/14.5）→ ② 还剩多少（数字 600/19，全卡唯一大字号）→ ③ 能不能用（右侧唯一状态位）→ ④ 下一步（底部唯一主操作）。

任何新字段进入卡片前必须先回答：它属于这四层里的哪一层？答不上来就不进卡片。

三条硬规则

一卡一重音：整张卡只允许一个实底/强色元素（主操作或异常徽标，二者互斥）。
颜色即状态：中性色不携带语义，只有异常与品牌操作可以使用彩色。
一卡一盒子：卡片内不再出现第二层描边容器，分区靠间距与发丝线。

05

两套刻度：字号 5 档、控件 3 档

现在的 8 档字号里有 4 档只差 1px，肉眼读不出区别，却让对齐变得困难。

档位字号 / 行高用途现状替代
micro11 / 16分组标签、单位、时间戳11px（139 处，混用于正文）
caption12 / 18辅助说明、tooltip、徽标12px（123 处）
body13 / 20正文与表格默认缺失 —— 被迫在 11 与 12 间二选一
title15 / 22卡片标题、账号名15px（12 处）与 14px（5 处）并存
display19 / 26关键数字、页面主数值无 —— 数字与标签同号，失去重量
控件高度用于说明
sm24px行内按钮、chips、徽标同时满足 WCAG 2.5.8 的 24×24 最小热区
md28px卡片操作、筛选器替代现有 21/23/28 三种混用
lg32px顶栏主操作、弹窗页脚替代 32/34/37 三种混用
为什么把正文定在 13px 而不是继续用 11px： 这是一个信息密度很高的工程工具，但「密」应该体现在每屏信息量，不是把字缩到 11px。 11px 中文在 1x 屏上的笔画会互相挤压（尤其「额/签/挂」这类密集字）， 而 13px 只比 11px 多占 1px 行高，换来的可读性提升远大于密度损失。
06

落地：三批，按「可独立验收」切

每批都能单独发布并回滚，不需要等全部完成。

Batch A

卡片与首屏重排

  • AccountCard.tsx：徽标内联、异常态徽标、删除能力行、额度数字升级
  • Dashboard.tsx：指标条单行 40px、副标题去重、分组头压缩
  • 统一 variant="full|compact"，托盘复用同一骨架
  • 验收：卡片 ≤ 168px，单卡彩色信号 ≤ 1
Batch B

语义令牌与刻度收敛

  • 新增 surface / border / fg 语义层，先与旧类并存
  • 按文件迁移中性色，删dark: 孪生（预计 −600 处）
  • 字号 5 档、控件 3 档写入 @theme，替换 text-[11px]
  • 验收：grep -c "dark:" 降到 300 以下
Batch C

明确不改的部分

✓对比度体系（浅/深色 0 失败）—— 任何改色都必须重新跑一遍遍历
✓动效降级与焦点环策略 —— 已经是行业上游水平
✓品牌绿作为唯一强调色 —— 不要为了「活泼」引入第二品牌色
✓吸顶筛选区 —— 工具多时这个设计是对的，只调高度不动结构
✓ARIA 语义（current / pressed / busy）—— 沿用
✓分组视图与平铺视图双模 —— 是真实需求，不合并
一句话验收标准：把重设计后的卡片缩到 50% 尺寸、模糊掉文字，用户仍然能指出「这张卡还剩多少」和「这张卡有没有问题」。 如果做不到，说明颜色仍然在承担它不该承担的职责。
